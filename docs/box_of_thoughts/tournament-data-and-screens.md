# Турнир: модель данных и экраны

Проекция решений из [`tournament-mode.md`](./tournament-mode.md) на Postgres и SPA. Не миграция и не код: поля, статусы, маршруты. Правила форматов там; здесь — где они лежат.

Клубные `fencers` / `matches` не трогаем. Турнирные бои **не** пишутся в `matches`. Живой бой по-прежнему только на устройстве.

## Сущности

Четыре таблицы. `club_id` дублируется на детях (как у `matches`), чтобы RLS остался `is_club_member(club_id)`.

```text
tournaments
tournament_participants
tournament_bouts          -- и слот очереди, и сохранённый бой
```

Места, оставшиеся выходы, пары следующего тура швейцарки — **считаются на клиенте** из участников + боёв, отдельных таблиц нет. Как статистика клуба.

### tournaments

```text
id                 uuid pk
club_id            uuid → clubs.id

name               text not null          -- обязательно; при создании подставить дату
status             setup | live | done

format             round_robin | playoff | groups_playoff | swiss | king_of_hill
                   null, пока не выбрали

points_scheme      half | binary | football | null
                   half = 0–0,5–1; binary = 0–0–1; football = 0–1–3
                   для playoff / king_of_hill всегда null
                   для остальных null до явного выбора; без выбора setup→live нельзя

time_limit_sec     int                    -- те же границы, что клубные настройки (60–300 / 5–20)
points_limit       int                    -- дефолт как у устройства, но хранится у турнира

group_count        int null               -- 2 | 4 | 8
advancers_per_group int null
swiss_rounds       int null               -- пишем в момент жеребьёвки: max(1, ceil(log2(n)))
koth_exit_limit    int not null default 3

created_at / updated_at
live_at            timestamptz null       -- нажали «начать проведение»
finished_at        timestamptz null
```

`setup` = чек-ин + выбор сетки + жеребьёвка (туда-сюда можно).  
`live` = проведение, назад к чек-ину нельзя.  
`done` = завершён; новых боёв из очереди нет, оверрайд счёта можно.

Удаление турнира — CASCADE участников и боёв.

### tournament_participants

```text
tournament_id      uuid → tournaments.id on delete cascade
fencer_id          uuid → fencers.id     -- без cascade delete фехтовальщика
club_id            uuid
pk                 (tournament_id, fencer_id)

group_no           int null              -- 1..group_count после жеребьёвки групп
```

Строка = человек в чек-ине. Пока `status = setup`, набор можно менять (insert/delete строк). После `live` набор заморожен.

Имя для таблиц: живое из `fencers`, на сохранённом бое — снимок, как в клубе.

### tournament_bouts

Одна таблица на слот и на результат. Пока боя не было — `finished_at is null`, счёт пустой, в очереди. После Save — заполненный ряд, в исходах.

Царь горы слотов заранее не создаёт: INSERT уже с результатом.

```text
id                 uuid pk                -- задаёт клиент (как matches)
tournament_id      uuid → tournaments.id on delete cascade
club_id            uuid

stage              rr | group | swiss | playoff | koth
group_no           int null
round_code         text null
                   swiss: '1','2',…
                   playoff: r32 | r16 | qf | sf | bronze | final
sort_order         int not null           -- порядок в блоке / критерий отдыха

blue_fencer_id     uuid null
red_fencer_id      uuid null
blue_placeholder   text null              -- 'g1p1' = 1-й группы 1; пока id ещё нет
red_placeholder    text null

winner_next_id     uuid null → tournament_bouts.id
loser_next_id      uuid null → tournament_bouts.id   -- бронза из полуфинала

blue_name / red_name         text null    -- снимок при Save
blue_score / red_score       int null
blue_result / red_result     win | lose | draw | null

time_limit_sec / points_limit / remaining_sec   int null
started_at / finished_at     timestamptz null

koth_king_id       uuid null              -- кто считался царём в этом бое (ничья = его победа)
```

Ограничения как у `matches`, но только когда бой сохранён (`finished_at not null`): разные бойцы, результат согласован со счётом.

Плей-офф: равный счёт запрещён и на Save, и на оверрайде.

Самоссылки `winner_next_id` / `loser_next_id`: победитель (проигравший) вписывается в синюю или красную сторону следующего слота (свободную / заранее назначенную).

Оверрайд: `UPDATE` только счёта и вычисленных `*_result` (+ пересчёт имён в следующих **несыгранных** слотах). Состав этого боя не меняем.

## Что создаётся на жеребьёвке

Пока `setup`. Смена состава или формата → стереть `tournament_bouts` и `group_no`, сгенерировать заново. Царь горы: жеребьёвка пустая, только параметры.

| format | строки bouts |
|---|---|
| round_robin | все пары `stage=rr`, оба id сразу, `sort_order` с отдыхом |
| playoff | полное дерево `n ∈ {2,4,8,16,32}`: ранние раунды с id, поздние с пустыми id; бронза если `n≥4` |
| groups_playoff | пары внутри групп + дерево на `G×q` человек; первый раунд плей-офф с placeholder `g{n}p{k}`, без id |
| swiss | только тур 1; туры `2..R` — когда предыдущий весь с `finished_at` |
| king_of_hill | ничего |

Швейцарка, нет пары: строки боя нет, зачёт только в клиентском подсчёте мест (баллы победы, уколов 0).

Переход `setup → live`: формат выбран; для rr/groups/swiss выбран `points_scheme`; для типов со слотами слоты есть; чек-ин ≥ 2 (плей-офф — ровно степень двойки ≤ 32).

## Пересчёт после Save и оверрайда

Клиент (и только он в v1):

1. Места / титулы / оставшиеся выходы.
2. Плей-офф: если у слота оба id и нет `finished_at` — его можно стартовать. Placeholder группы резолвится, когда **эта** группа вся сыграна; ничья на границе — модалка, в слот пишется выбранный id.
3. Швейцарка: если тур `k` закрыт и тура `k+1` ещё нет — вставить пары (близкий балл, без повтора если возможно, `sort_order` с отдыхом).
4. Оверрайд раннего боя: места пересчитать; **несыгранные** слоты пересобрать (плей-офф id/placeholder, будущие туры швейцарки). Уже сохранённые последующие бои не удаляем.

## RLS и запись

Как ростер: член клуба читает/пишет свои турниры. В отличие от `matches`, здесь нужны **UPDATE** (статус турнира, заполнение слотов, оверрайд счёта) и **DELETE** (удалить турнир).

Турнирный Save в v1 **без outbox**: нет сети — ошибка, слот не закрыт. Клубный outbox не смешиваем.

## Экраны

Клубная фича: `ClubRoute`, не Quick bout. Иконка в том же ряду, что Fencers / History / Stats (табло, фехтовальщики, история, статистика, настройки).

### Маршруты

```text
/tournaments                 список
/tournaments/:id             тело турнира (шаг зависит от status)
/                            табло; турнирный слот — query
```

Query табло:

- слот: `/?t=<tournamentId>&b=<boutId>` — подставить синего/красного, Save = UPDATE этого ряда;
- царь горы: `/?t=<tournamentId>` — селекты свободны, Save = INSERT `stage=koth`.

На табло полоска: название турнира + ссылка назад на `/tournaments/:id`. Без неё судья теряется (контекст в голове, как договаривались; полоска — минимальная зацепка, не блокировка селектов).

### Список `/tournaments`

- Карточки: название, статус (setup / live / done), тип сетки если уже выбран, дата `created_at`.
- Незавершённые и завершённые в одном списке, сверху новые.
- Кнопка нового: сразу INSERT с `name =` локальная дата, `status=setup`, лимиты с устройства, `koth_exit_limit=3`, `format` и `points_scheme` null → переход на `/:id`.
- Удаление с подтверждением (любой статус).

### Тело `/tournaments/:id`

Один экран, шапка: название (поле; пустое нельзя), статус, «назад к списку».

**status = setup**

1. Чек-ин: список активных `fencers` клуба, отметить присутствующих. Гостя нет в списке → сначала `/fencers`. Мало людей / не степень двойки — тип плей-офф просто нельзя выбрать, не квота.
2. Формат и параметры (когда чек-ин уже виден):
   - тип сетки;
   - схема баллов — ни одна не выбрана, обязательна для rr / groups / swiss;
   - группы: число групп 2/4/8 и выходящих так, чтобы `G×q = 2^k`;
   - швейцарка: показать посчитанные туры, не редактируем в v1;
   - царь горы: лимит выходов, дефолт 3;
   - ползунки времени и уколов турнира.
3. Кнопка жеребьёвки (царь горы — не нужна). Можно снова чек-ин: слоты снести.
4. «Начать проведение» → `live`. Нельзя без формата; без схемы, если она нужна; без слотов, если они нужны.

**status = live** — четыре поверхности (табы или сегменты, узкая ширина как у клубной навигации):

| Поверхность | Содержание |
|---|---|
| Queue | по типу из `tournament-mode.md` §13. Старт слота → `/?t=&b=`. Царь горы: список оставшихся выходов, старта слота нет, ссылка на `/?t=` |
| Table | промежуточные места §13 |
| Bouts | исходы, как `/history`, без попадания в клуб. Тап → оверрайд счёта (два поля, статус из счёта, предупреждение про итоги). Плей-офф: равный счёт нельзя |
| Board | по сути уход на `/` с query |

«Завершить» всегда доступна → `done`.

Модалка ничьей на выходе из группы: два имени, выбрать одного, записать id в слот. Несколько групп — очередь окон.

**status = done** — только Table (финальная) и Bouts (оверрайд с тем же предупреждением). Queue и старт новых боёв скрыты.

## Табло в турнирном контексте

Клубный Index почти как есть. Добавляется:

- чтение `t` / `b` из URL;
- если есть `b` — подставить бойцов слота (селекты как в клубе, в v1 не запираем, кроме того что слот знает своих);
- Save: не `matches`, а турнирный bout; после успеха — тост и ссылка/возврат к `/tournaments/:id`;
- плей-офф: Save draw заблокирован с поп-апом (уже решено);
- царь горы: селекты живые; при ничьей в запись `koth_king_id` = победитель прошлого koth-боя этого турнира, если он снова на табло, иначе тот, кого судья оставил первым / синим — зафиксировать в реализации одно правило: **синяя сторона = царь, если прошлого царя нет на табло**.

Лимиты таймера на этом бою — с турнира, не из `localStorage` (ползунки турнира). Клубные настройки устройства для клубного боя не меняются.

## Навигация

На Index, Fencers, History, Stats, Settings, список турниров — одна полоса иконок. Турниры — четвёртая клубная иконка (между людьми и историей или после статистики — в реализации выбрать место и везде одинаково).

Узкая ширина: как сейчас, иконки отдельной строкой.
