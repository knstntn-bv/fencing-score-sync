# Турнирный режим — черновые рассуждения

Не спецификация и не план реализации. Заметки, чтобы не потерять рамку: чем турнир отличается от клубного режима и что легко забыть, если начать с «типов сетки».

Клубный режим здесь — текущий продукт: свои люди, свои бои, бой самодостаточен. Турнирный — отдельный законченный процесс со стадиями и сеткой.

Исходная рамка:

1. У турнира явное начало и конец, это законченный процесс.
2. Явные стадии: регистрация, генерация сетки, проведение (возможно поэтапное), подведение итогов.
3. Несколько вариантов сетки (уточнено ниже: выбор из пресетов, без конструктора комбинаций).

Ниже — уточнения по порядку. Рамки и чек-ин зафиксированы. Этот круг — типы сеток.

## Решения

### Масштаб: локальный клубный турнир

Система для турниров внутри клуба (зал, свой состав, свой тренер/организатор). Не федерация, не открытая запись с улицы, не многодневный турнир на десятках дорожек.

Следствие: не закладывать квоты, допуски, публичную регистрацию, лист ожидания, межклубный портал, роли «участник / родитель / главсуд» как отдельные продукты. Если что-то из этого понадобится — это уже другой масштаб, не эта модель.

Роли схлопываются к тем, кто и так ведёт клуб: тот же человек чекинит, жребий запускает и пишет счёт. Дорожек мало. Состав — ростер клуба (гость, которого нет в списке, сначала появляется как фехтовальщик клуба, а не как отдельная турнирная сущность).

Практичный дефолт на этом масштабе: **один турнир = одно событие = один список на жеребьёвку**. Несколько оружий за вечер — несколько турниров, а не контейнер «чемпионат с дисциплинами». Команды — не сейчас.

### Состав: в приложении только чек-ин

Стадия «регистрация» в приложении — это **чек-ин в зале**: отметить, кто сегодня стоит в списке.

- Квоты, возрастные/рейтинговые допуски, приглашения, лист ожидания, wild card — **за скоупом**. Это решает человек с планшетом, а не правила в системе.
- Инвариант: **кто в списке на момент жеребьёвки — тот в жеребьёвке**. Нет второго фильтра «записался, но не пришёл». Список чек-ина и вход жеребьёвки — одно и то же множество.
- Пока жеребьёвка не запущена, человека можно добавить или убрать. Это не «снятие с турнира», а правка списка присутствующих.
- После жеребьёвки список участников для этой сетки уже не чек-ин. Неявка, травма, дисквалификация — другая стадия (проведение / исключения), не регистрация.

Переименование в голове: исходные стадии лучше читать как **чек-ин → жеребьёвка → проведение → итоги**. Слово «регистрация» оставить для бумажной/чат-записи до зала, её приложение не ведёт.

### Формат: выбор типа, не конструктор этапов

Организатор не собирает турнир из этапов. Он выбирает один тип из списка. «Плей-офф с группами» — это именованный пресет (внутри него круговая + выбывание), а не общий комбайнер «любой формат после любого».

Набор:

1. **Круговая** — каждый с каждым; места по турнирным баллам, призёры — первые трое.
2. **Плей-офф** — чистое выбывание; в v1 только `n = 2^k`; в таблице сразу бой за 3-е.
3. **Плей-офф с группами** — круговые группы, затем плей-офф из выходящих; сумма выходящих = `2^k`; в v1 только чётное число групп.
4. **Швейцарская** — туры по результатам; нет пары — автоматический зачёт.
5. **Царь горы** — без жеребьёвки, лимит выходов по умолчанию 3; селекты на табло; три титула.

Тип выбирают, когда список чек-ина уже виден: от `n` зависят размер плей-офф, нарезка групп, число кругов швейцарки. Зафиксировать «сегодня швейцарка» заранее можно, параметры — после списка.

Стадии из-за этого чуть плывут: у типов 1–4 после чек-ина есть генерация пар/таблицы; у царя горы генерации нет, сразу проведение под ограничением выходов.

### Проведение v1: одна дорожка

В первой версии дорожка одна. Все бои — одна очередь на одно табло. Параллельных пулов нет; бои из разных групп, разных туров швейцарки или (когда сетка уже это позволяет) плей-офф просто чередуются в этой очереди.

Критерий порядка очереди: **минимизировать ситуацию «один человек в двух боях подряд»**. Не относится к чистому плей-офф (порядок диктует сетка) и к царю горы (победитель как раз должен остаться).

Для круговой — последовательность всех пар. Для групп — можно и нужно мешать группы: бой из группы A, затем из B, людям как раз отдых. Для швейцарки внутри тура пары и так не пересекаются (матчинг); стык туров — не ставить первым боем следующего тура того, кто только что фехтовал. Когда избежать подряд нельзя (трое в круговой) — оставляем как есть, это не ошибка генерации.

## 1. Турнир ≠ одно событие

Для клубного масштаба это **не цель первой модели**: один турнир — один список — одна сетка. Ниже — зачем федеративные системы делают контейнер, и почему нам это рано.

На практике «турнир» часто контейнер:

- несколько **событий** (шпага мужчины, рапира U14, сабля женщины…);
- у каждого события своя категория, лимит участников, формат и сетка;
- общий день, общие дорожки и судьи, но независимые итоги.

Если это не развести, потом придётся либо плодить «мини-турниры», либо пихать разнородные сетки в одну сущность.

Отдельно: **личный** vs **командный**. Команды — это состав, замены, эстафета, иной подсчёт. Даже если «пока только личка», контейнер лучше сразу мыслить как «событие с типом».

## 2. Типы сеток (уточнено)

Конструктор «этап + правило перехода» не делаем. Пять пресетов. Посев / защита одноклубников / ручная перестановка — общий слой; для клуба дефолт генерации случайный, пока не решим иначе.

Общий кусок для круговой и групп (и логично для швейцарки, пока не скажем иначе): схема баллов за бой. Организатор выбирает одну тройку «проигрыш — ничья — победа»:

- `0 — 0,5 — 1`
- `0 — 0 — 1`
- `0 — 1 — 3`

После каждого боя эти баллы пишутся в турнирную таблицу. Это не уколы на табло: уколы остаются счётом боя и нужны только как тай-брейк.

### 2.1 Круговая

Полный граф: `n` людей → `n(n-1)/2` боёв, у каждого `n-1` бой. Второго этапа нет.

Места: сортировка по турнирным баллам. На экране у каждого: баллы, набранные уколы (зелёным), пропущенные (красным, со знаком минуса). Это закрывает двусмысленность «очки в боях»: не один индикатор, а два столбца. При равенстве баллов для порядка строк, пока не скажем иначе, выше больше зелёных, затем меньше модуля красных; если и это совпало — делёж места (два третьих). Призёры — первые трое в этом порядке.

Очередь боёв — линейный список пар, без группировок. Порядок списка — уже принятый критерий отдыха (не два боя подряд у одного, когда возможно).

### 2.2 Плей-офф

Одно поражение — вылет, плюс **бой за 3-е** между проигравшими полуфиналистами.

В первой версии **только** `n ∈ {2, 4, 8, 16, 32}`. Больше 32 — чистый плей-офф недоступен, это уже группы. Bye и схемы обхода не делаем; если на чек-ине не степень двойки — тип недоступен. Для `n = 2` есть только финал, боя за 3-е нет. С `n = 4` таблица: два полуфинала, финал, бронза. С `n = 32` самый ранний раунд — 1/16 финала.

Места 1–4 из таблицы читаются прямо. Ниже — «вылетел в раунде X», без утешения.

Сохранение боя при равном счёте в плей-офф запрещено (поп-ап). Кнопки уколов после нуля таймера работают — дофехтовать до победы и сохранить.

### 2.3 Плей-офф с группами

Снаружи один тип. Внутри: круговые группы (та же схема баллов и тот же тай-брейк уколами, что в 2.1), затем плей-офф из выходящих.

Параметры организатора: число групп (и/или размер), **сколько выходит из группы** так, чтобы **сумма выходящих из всех групп = 2^k**.

В v1 **только чётное число групп** — проще кросс-жеребьёвка плей-офф (1-я группа против 2-й и т.д., первые не встречаются с своими во втором этапе сразу).

Важное следствие, если из каждой группы выходит одно и то же `q`: сумма `G × q = 2^k` при целом `q ≥ 1` возможна, только когда само `G` — степень двойки. Чётные 6, 10, 12, 14 **не стыкуются** (шесть групп по одному выходящему → 6 в плей-офф, это не степень двойки). Практически v1 = группы `2 / 4 / 8`, не любое чётное. Неровные размеры групп при этом нормальны (13 человек, 4 группы → 4+3+3+3).

Ничья на границе выхода: тот же порядок, что в круговой. Если и уколы не развели — **ручной выбор**. При формировании сетки плей-офф модальное окно: два бойца, выбрать одного выходящего. Несколько групп с неоднозначностью — несколько окон подряд. Тройную ничью в v1 отдельно не проектируем. Правки уже сохранённого боя нет.

Плей-офф после групп — та же таблица, что в 2.2 / 13.2, включая бой за 3-е (когда выходящих ≥ 4). Выходящие **раскладываются по сетке равномерно**: в первом раунде плей-офф люди из одной группы не встречаются. Слоты первого раунда задаются при жеребьёвке как места («1-й группы A vs 2-й группы B»); имена появляются, когда соответствующая группа дофехтовала все свои бои, не раньше и не по «уже точно вышел».

### 2.4 Швейцарская

Весь турнир, без среза в финал. Число туров задаёт организатор. Пары тура — по текущим баллам, по возможности без повтора; если в маленьком зале повтор неизбежен — разрешать явно.

Нет пары (нечётный `n`, или иначе не склеить) — **автоматический зачёт**: человек проходит тур с баллами победы по выбранной схеме. Уколов в этом туре нет (0:0 / пусто), чтобы зачёт не становился «виртуальной дуэлью». Одного человека не стоит кормить зачётом каждый тур подряд, если есть кому отдать — это гигиена парности, можно во второй итерации.

Итог: таблица мест как у круговой (баллы, зелёные / красные уколы). Бухгольц не тащим. Очередь — по турам: следующий тур появляется только когда сыгран предыдущий. Число туров **считается из `n`**. Формулу вслух не назвали; в заметке пока `max(1, ceil(log2(n)))` (8 человек → 3 тура). Ручная правка числа до точки невозврата не оговаривалась — пока автоматическое.

### 2.5 Царь горы

Жеребьёвки нет. Лимит выходов по умолчанию **3** (параметр до точки невозврата).

Очереди пар нет. Первый царь и первый претендент — обычные селекты на табло. Селекты **остаются активными** все проведение: слота нет, «замена состава» здесь как раз норма. Контроль лимита выходов **вручную**: приложение не запрещает выбрать человека с нулём и не подсказывает следующего.

Ничья на табло (равный счёт при Save) = победа царя (серия жива; для титулов царю +победа). Царь для этого правила — победитель предыдущего сохранённого боя, если он снова на табло; иначе это снова «первый бой» (оба вышли селектами).

Итог — три титула (победы / серия / кто остался последним), плюс таблицы в 13.5. Оверрайд счёта — из таблицы исходов, как у остальных типов (см. 6).

## 3. Чек-ин (уточнено)

Федеративная нарезка «заявка → допуск → чек-ин → жеребьёвка» для клубного зала лишняя. В приложении один список.

Что из этого следует:

- Источник имён — ростер клуба. Чек-ин = выбрать людей из уже известных фехтовальщиков. Нового человека сначала заводят в ростер (как сейчас), потом отмечают в турнире. Турнир не заводит параллельную картотеку.
- Один человек в одном турнире один раз.
- Пустой список и список из одного — жеребьёвку запускать бессмысленно. Квот нет, но нужен простой стоп: «мало людей», а не правила допуска. Для чистого плей-офф дополнительно: `n ∈ {2, 4, 8, 16, 32}`, иначе тип недоступен.
- Опоздал до жеребьёвки — его просто добавляют в список. Опоздал после — это уже не чек-ин; либо пережеребьёвка (отдельное решение), либо он вне сетки.
- Закрытие чек-ина = переход к формату: для типов 1–4 это генерация сетки, для царя горы — задание лимита выходов и старт боёв. Отдельную сущность «запись закрыта, сетки ещё нет» не держим, пока не понадобится.

Что сознательно не моделируем: заявка заранее, подтверждение явки отдельным статусом, waitlist, «зарегистрирован, но не допущен».

Открытым на этом слое остаётся только быт, не правила допуска:

- кто из клубных ролей может править список (скорее те же, кто правит ростер);
- можно ли чекинить с нескольких планшетов сразу (для зала из 15 человек обычно один планшет).

## 4. Жеребьёвка — отдельный продукт, не кнопка «сгенерировать»

Зависит от типа. Царь горы её не делает. Круговая генерирует полный набор пар. Плей-офф в v1 — дерево без bye, только `n ∈ {2, 4, 8, 16, 32}`, с матчем за 3-е. Группы — состав групп плюс потом дерево из выходящих (чётное / фактически `2/4/8` групп). Швейцарка — только пары **первого** тура; остальные туры после результатов; нет пары — зачёт.

Общий слой, ещё не фиксировали (и для клуба можно сильно упростить):

- **посев**: рейтинг, прошлые турниры, ручной посев, случайный — дефолт случайный;
- **защита** одноклубников: внутри одного клуба почти бессмысленна;
- **заморозка** после генерации; пережеребьёвка до первого боя.

Сетка (где она есть) должна быть воспроизводимым фактом: кто, когда, из какого списка, каким типом. Иначе споры неразрешимы.

## 5. Проведение (уточнено)

В v1 ресурс один: одна дорожка, одно табло, одна очередь боёв. Назначение на дорожку, судьи, параллельность — за скоупом.

Очередь строится так, чтобы человек по возможности не выходил два раза подряд. Это правило **порядка**, не формата:

- **круговая** — полный список пар, уложенный с отдыхом;
- **группы** — бои разных групп чередуются на той же дорожке, это как раз помогает отдыху;
- **швейцарка** — внутри тура пересечений нет; между турами тот же критерий на стыке;
- **плей-офф** — порядок раундов (четверть → полуфинал → бронза → финал), отдых не оптимизируем;
- **царь горы** — очереди пар нет, селекты на табло, лимит глазами.

Формат самого боя: те же лимиты времени и уколов, что в клубе, но **задаются в турнирном режиме** (свои ползунки у турнира, не только `localStorage` устройства). Ничья как результат:

- **круговая / группы / швейцарка** — обычное «Save draw», баллы по выбранной тройке;
- **плей-офф** — сохранение при равном счёте **нельзя**. Поп-ап: нужен победитель. Кнопки +/− после нуля таймера остаются активными (как в клубе), судья говорит «до победы» и ставит укол, после чего Save проходит как victory;
- **царь горы** — равный счёт сохранять можно, формат читает это как победу царя; селекты бойцов на табло активны.

Клубный режим: выбрали двоих и пошли. Турнирный v1: следующее имя в очереди на том же табло.

## 6. Исключения важнее счастливого пути

Сетка живёт, пока все пришли и все дофехтовали. Ломается на:

- неявке (победа без боя, пересчёт посева, дыра в пуле);
- снятии в середине DE;
- незавершённом бое (травма, карточка, дисквалификация);
- ничьей на табло в плей-офф (закрыто: Save нельзя, дофехтовать) и в царе горы (закрыто: победа царя);
- спорном ударе / протесте / пересмотре;
- ошибочно внесённом счёте и **исправлении после**;
- чёрной карточке (исключение из турнира, а не только из боя).

Ошибочный счёт правится **оверрайдом из таблицы исходов**, не с табло.

Содержательно: меняется **только счёт** (два числа уколов). Состав пары не трогаем. Статус победа / проигрыш / ничья считается сам, как на клубном Save: больше уколов — победа, равный счёт — ничья. Дальше формат читает статус по своим правилам (плей-офф ничью по-прежнему не принимает — оверрайд в равный счёт там нельзя; царь горы при ничьей = победа царя).

Перед записью — предупреждение: пересчёт может **перепахать итоги** (места, выходящих из групп, незаполненные слоты плей-офф и ещё не сыгранные туры швейцарки). Уже сохранённые последующие бои сами не удаляем: предупреждение как раз про то, что картина может разъехаться. Неявка без боя, снятие, карточки — по-прежнему не моделируем.

Выбор выходящего из группы при ничьей баллов — не оверрайд боя, а шаг формирования сетки.

## 7. Итог — не только победитель

Места 1–2–3 очевидны. Дальше:

- как классифицируются вылетевшие в 1/8;
- считается ли бой за 3-е;
- индикаторы пулов (V, разница уколов) и тай-брейки при равенстве;
- кто «прошёл в DE», если мест меньше, чем желающих;
- итоговый протокол vs живая таблица «ещё не всё дофехтовали».

Для круговой нужны критерии мест. Для швейцарки — Buchholz и компания. Для DE — правило незавершённых ветвей. Это часть формата, не «экран кубка».

## 8. Люди и права

Клубный режим: свои, свои дорожки, свои бои.

Турнир:

- организатор / главсуд;
- секретариат (сеток и протоколов);
- судья на дорожке;
- оператор пульта (текущее табло);
- участник (видит свои бои, не чужие настройки);
- зритель / родитель (публичная сетка).

И отдельно: **чей ростер**. Только клуб? Несколько клубов? Разовые гости? Турнир сразу становится межклубным, даже если проходит в одном зале. Иначе турнирный режим — просто «клубный день с датами».

## 9. Связь с клубным режимом

Решено: турнирный бой **не** клубный матч. В `/history` и `/stats` не попадает. Разминка вне сетки — это просто уйти на клубное табло (в v1 без защиты от путаницы).

Офлайн/outbox для турнира позже: клубный outbox про самодостаточный матч, турнирный слот ломает сетку, если «сохранилось только на планшете».

## 10. Время как сущность

«Начало и конец» стоит декомпозировать:

- публикация и закрытие записи;
- окно чек-ина;
- момент жеребьёвки (и запрет менять состав);
- старт/пауза/перенос дня;
- пауза между пулами и DE;
- отмена турнира (с уже записанными людьми).

Турнир ещё и **календарный объект**: многодневность, зал занят до 18:00, оружие после обеда.

## 11. Продуктовые края

- черновик vs опубликованный турнир;
- шаблон («субботний турнир клуба») vs разовый;
- публичная ссылка на сетку без логина;
- уведомление «ты на дорожке 3»;
- повтор того же состава через неделю — это новый турнир, не продолжение;
- что считается официальным источником: приложение, бумажный протокол, FIE/национальная система.

## 12. Как турнир ложится в приложение

Не схема данных, а каркас экранов. Клубные `/`, `/fencers`, `/history`, `/stats` остаются; турнир — отдельная ветка плюс то же табло.

### Экраны и жизненный цикл

Отдельный экран турниров: список (завершённые **и** незавершённые) + старт нового + **удаление**. У турнира **обязательное название**, по умолчанию подставляется дата; поле можно отредактировать, пустым пройти нельзя.

После старта:

1. **Чек-ин** — он же регистрация.
2. **Выбор типа сетки, параметры, жеребьёвка.** Отсюда можно вернуться к чек-ину и перезапустить жеребьёвку.
3. Отдельная кнопка **начать проведение** — точка невозврата. Назад к чек-ину нельзя. Схема баллов по умолчанию **не выбрана**; без явного выбора схемы (для круговой / групп / швейцарки) кнопку нажать нельзя. Плей-офф и царь горы схему не используют. Боёв к этому моменту ещё может не быть.
4. **Проведение.** Кнопка **завершить** доступна досрочно, не только после последнего боя.
5. **Завершённый** турнир: таблица исходов по боям и таблица финальных результатов. Сетку заново не жеребим; **счёт уже сыгранного боя** можно поправить оверрайдом из исходов (с предупреждением) — итоги пересчитаются.

В проведении доступны:

- табло (уже есть);
- таблица следующих боёв с кнопкой старта: открывает табло с уже проставленными бойцами. **Замены состава слота нет**, кроме царя горы (там слота нет, селекты живые);
- таблица исходов по боям — только внутри турнира; отсюда оверрайд счёта (статус из счёта, с предупреждением про итоги);
- таблица промежуточных результатов — вид зависит от типа сетки.

У царя горы вместо очереди пар — список участников с оставшимися выходами (больше осталось — выше). Выбор пар только селектами на табло.

Уйти в клубный режим можно; состояние турнира сохраняется, возврат со списка. В v1 **не** защищаем табло от клубного выбора бойцов и не поднимаем живой бой выше Index: переход в клуб не задуман как полноценная работа на табло, это чтобы не плодить блокировки. Контекст в голове судьи. Незасейвленный бой на `/` при уходе на другую страницу пропадёт, как сейчас.

### Досрочное завершение

Автозавершения нет. Организатор жмёт «завершить», итог считается по уже сыгранным боям.

Явно нужно:

- **круговая** — таблица мест по состоявшимся боям (у кого боёв меньше, баллов может быть меньше: это принимаем, отдельных поправок на «неравное число боёв» в v1 нет);
- **царь горы** — три титула по текущему состоянию, даже если лимит выходов не исчерпан.

Ту же кнопку не стыдно дать в плей-офф / группах / швейцарке: сетка просто остаётся недоигранной, места и титулы — по тому, что успели. Если для выбывания это слишком свободно, потом ограничим; один контрол проще двух политик.

### Турнирные бои ≠ клубные

Бои турнира **не** пишутся в `/history` и **не** входят в `/stats`. Клубный матч и турнирный слот — разные сущности. Save с табло, открытого из очереди турнира, закрывает слот и обновляет турнирные таблицы, не клубную историю.

Селекты на клубном табло в v1 остаются как есть: слот подставляет имена, судья теоретически может их сменить до Start. Отдельного сценария «замена бойцов» нет; полагаемся на то, что очередь запускают как есть.

### Оверрайд счёта

Из таблицы исходов, в проведении и после завершения. Только два числа уколов. Победа/ничья/поражение из счёта. Предупреждение, что итоги перепашутся. Пару и имена не меняем. В плей-офф равный счёт по-прежнему нельзя. Клубный `/history` этого не умеет и не должен.

### Удаление

Отдельная кнопка, не «завершить». Черновик, идущий и завершённый можно убрать из списка (с подтверждением). Удалили — нет ни сетки, ни исходов. Несколько незавершённых в списке допустимы: лишнюю блокировку «только один идущий» не ставим.

## 13. Таблицы по типам сеток

Общие поверхности проведения: очередь следующих боёв, исходы, промежуточные/финальные места. Исходы везде похожи на клубную историю, но живут внутри турнира. Очередь и места — разные.

### 13.1 Круговая

**Очередь** — плоский список пар, без заголовков групп и без туров. Строка = следующий бой. Сыгранное из очереди уходит в исходы. Порядок — минимизация двух боёв подряд у одного человека.

**Промежуточные (и финальные) места** — линейный список всех участников, отсортированный по баллам:

- турнирные баллы (схема 0–0,5–1 / 0–0–1 / 0–1–3);
- набранные уколы, зелёным;
- пропущенные уколы, красным и со знаком минуса (как `-12`, не «12 пропущено»).

Досрочное завершение показывает ту же таблицу по уже сыгранным боям: у кого меньше боёв, тот обычно ниже по баллам, отдельные «коэффициенты за несыгранное» не вводим.

Нумерация мест на экране не оговаривалась: достаточно порядка строк (первый = лидер). Призёры — верхние трое, отдельными медалями в v1 можно не метить.

### 13.2 Плей-офф

Чистый плей-офф в v1 только при `n ∈ {2, 4, 8, 16, 32}`. Больше 32 человек — этот тип не включаем, дальше объективно группы.

И очередь, и промежуточная таблица — **одни и те же блоки раундов**, снизу вверх:

- финал (внизу);
- над ним — бой за 3-е (если `n ≥ 4`);
- 1/2, 1/4, 1/8, 1/16 — только те раунды, которые есть при данном `n`.

Сверху экрана самый ранний раунд (при 32 людях — 1/16), внизу финал. Проведение идёт сверху вниз. Критерий «не два боя подряд» здесь не действует: порядок диктует сетка.

Каждый бой — **двойная строка**: две половины друг над другом. В каждой: имя, счёт, метка «прошёл в следующий раунд» или «вылетел». Пока боя не было — счёт и метка пустые. Пока победитель предыдущего раунда неизвестен — имя в следующем раунде пустое; таблица следующего раунда **наполняется по ходу** текущего.

Очередь от промежуточной отличается кнопкой старта на бое, где уже есть оба имени и ещё нет исхода. Замены состава нет: старт подставляет тех, кто в слоте.

Бой за 3-е: проигравшие полуфинала, метки «3-е» / «4-е» (не «вылет в 1/2» vs переход в финал). Финал: «1-е» / «2-е». Вылетевшие раньше финала так и остаются с меткой вылета в своём раунде — отдельного линейного рейтинга, как в круговой, нет.

Досрочное завершение: та же сетка, незаполненные слоты пустые, призёров может не быть.

### 13.3 Плей-офф с группами

Очередь и промежуточные — склейка 13.1 и 13.2, не третий виджет.

**Очередь.** Сначала блоки групп: в каждом — плоский список пар этой группы, как круговая. Затем блоки плей-офф снизу вверх (финал / бронза / 1/2 / …), как чистый плей-офф. На одной дорожке по-прежнему можно брать следующим бой другой группы (критерий отдыха); группировка на экране — про читаемость, не про запрет чередовать. Старт плей-оффного слота — только когда в двойной строке уже оба имени.

**Промежуточные места.**

- На группу — своя круговая таблица: баллы, зелёные набранные, красные пропущенные со знаком минуса, тот же порядок строк.
- Ниже (или тем же свитком дальше) — сетка плей-офф двойными строками.

Первый раунд плей-офф наполняется **по факту завершения группы**: дофехтовали группу A — в свои слоты встают её выходящие, даже если группа B ещё идёт. Сосед по первому раунду может ещё быть пустым. Имена следующих раундов плей-офф — как в 13.2, от победителей предыдущего.

Посев в сетку при жеребьёвке: выходящие из одной группы **равномерно** по разные ветки, в первом раунде не встречаются. Типичный каркас при двух группах и двух выходящих: `1A–2B`, `1B–2A`. При четырёх группах — тот же принцип кросса, без сведения своих в 1/8. Точную матрицу слотов можно дописать формулой в реализации; правило одно: не свои в первом раунде и равномерный разброс по половине сетки.

Досрочное завершение в группах: круговые блоки по сыгранному, плей-офф может остаться пустым.

### 13.4 Швейцарская

**Очередь** — блоки туров. Тур 1 известен после жеребьёвки. Тур `k+1` **не заполняется**, пока не сохранены все бои тура `k` (зачёт без пары — не слот на табло: человеку сразу пишутся баллы победы, уколов нет). Внутри тура пары не пересекаются; порядок строк в блоке — критерий отдыха, в том числе на стыке с последним боем предыдущего тура, когда новый блок только появился.

**Промежуточные (и финальные) места** — как круговая: список участников по баллам, набранные уколы зелёным, пропущенные красным со знаком минуса, тот же вторичный порядок при равенстве баллов.

Досрочное завершение — та же таблица по сыгранным турам; неначатый следующий тур просто не существует.

### 13.5 Царь горы

**Вместо очереди** — список участников с **оставшимися выходами**, сортировка: больше осталось — выше. Это шпаргалка для зала, не генератор пар и не блокер. Колонку можно считать по сохранениям (входящий −1, оставшийся царь не тратит), но селекты на табло **не** смотрят на неё: выйти можно с нулём.

Первый царь и претендент, каждый следующий бой — селекты на табло, как в клубе. Кнопки старта слота нет.

**Промежуточные (и финальные) места** — полный список участников: число побед и самая длинная серия, сортировка по победам. Три титула по-прежнему можно подсветить отдельно (победы / серия / кто остался на дорожке последним); они могут совпасть.

Досрочное завершение — те же два списка по уже сыгранному.
