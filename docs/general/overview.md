# Fencing Scorer — обзор

Судейское табло для клубных боёв. Живой счёт и таймер всегда на устройстве. Ростер и сохранённые бои — в Supabase, если настроен клубный аккаунт.

Сайт: [fencing-scorer.konbo.me](https://fencing-scorer.konbo.me/). Интерфейс на английском.

Связанные заметки:

- [логика окончания боя](./bout-end-rules.md)
- [фехтовальщики, история, статистика](./fencers-and-match-history.md)

## Режимы

| Режим | Когда | Что доступно |
|---|---|---|
| Без Supabase | нет `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` | табло и настройки; ростер/история/статистика показывают заглушку |
| Клубный аккаунт | ключи есть, пользователь вошёл | полный набор: выбор бойцов, Save, `/fencers`, `/history`, `/stats` |
| Quick bout | ключи есть, гость с экрана логина | только таймер, счёт и локальные настройки; Save и клубные страницы закрыты |

Гостевой флаг живёт в `sessionStorage` (`fencing-scorer:v1:guest-bout`) и сбрасывается при входе в аккаунт.

## Экраны

- **Логин** — email + пароль, создание клубного аккаунта, **Quick bout**.
- **Табло** `/` — две стороны (синяя / красная), таймер, Reset с удержанием 1 с, настройки через шестерёнку.
- **Настройки** `/settings` — лимиты времени и очков на этом устройстве; для вошедшего — карточка аккаунта и выход.
- **Фехтовальщики** `/fencers` — добавить, переименовать, архивировать, восстановить.
- **История** `/history` — сохранённые бои, фильтр по человеку.
- **Статистика** `/stats` — бои / победы / поражения / ничьи и частые соперники.

На узкой ширине иконки навигации стоят отдельной строкой, чтобы заголовок не обрезался.

## Что где хранится

**Только устройство**

- идущий бой (`useState`: счёт, таймер, выбранные стороны);
- лимиты: `localStorage` `fencing-scorer:v1:settings` (по умолчанию 90 с / 12 очков);
- кэш активных фехтовальщиков: `fencing-scorer:v1:fencers:{clubId}`;
- очередь неотправленных боёв: `fencing-scorer:v1:outbox:matches:{clubId}`.

**Supabase** (после входа)

- `fencers` и `matches`;
- `club_id = auth.uid()`;
- в клиент только anon key.

Схема: `supabase/final_schema.sql` и `supabase/README.md`.

## Табло

- Старт таймера: оба анонимны **или** два разных именных бойца. Один выбранный — нельзя.
- Пока таймер идёт: +/− и Reset выключены, экран старается не гаснуть (Capacitor KeepAwake / Screen Wake Lock).
- Имена после первого Start фиксируются снимком.
- Анонимный бой и Quick bout в таблицу не пишутся.
- Именной бой сохраняется кнопкой Save (см. [bout-end-rules](./bout-end-rules.md)).

## Настройки

Ползунки: время 1–5 мин с шагом 10 с, очки 5–20. **Save Settings** пишет только `localStorage` и не зависит от сети.

## Сборка и деплой

- Vite + React + TypeScript, порт dev-сервера **8080**.
- GitHub Actions (`.github/workflows/deploy-pages.yml`) собирает `dist/` и публикует Pages. Секреты `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` нужны продовой сборке.
- `CNAME`: `fencing-scorer.konbo.me`. Для SPA копируется `404.html`.

## Capacitor

Тот же веб-бандл (`webDir: dist`). Папки `android/` и `ios/` в git не лежат — добавляются локально (`npx cap add`). В конфиге нет постоянного `server.url`: нативное приложение грузит упакованный `dist`, а не удалённый сайт. Live-reload на устройстве — через `CAPACITOR_LIVE_RELOAD_URL`.

## Не делается

- realtime-табло на втором экране;
- карточки, приоритет, периоды 3×3 по FIE;
- несколько клубов и роли тренер/судья;
- правка уже сохранённого боя;
- автосохранение по нулю таймера.
