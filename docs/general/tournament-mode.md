# Турнирный режим

Как провести клубный турнир в зале и как это устроено в коде. Живой бой по-прежнему только на устройстве. Турнирные протоколы **не** клубные `matches`: история и статистика клуба их не показывают.

Сайт — тот же SPA. Интерфейс английский. Черновые рассуждения — [`docs/box_of_thoughts/tournament-mode.md`](../box_of_thoughts/tournament-mode.md). Исторический план этапов — [`docs/implementation_plans/IMPLEMENTED-tournament-mode.md`](../implementation_plans/IMPLEMENTED-tournament-mode.md).

## Для зала

Турнир — законченный клубный вечер: чек-ин своих и гостей, один выбранный формат, бои на одной дорожке, таблица / сетка, конец события. Не федерация, не открытая запись, не несколько дорожек и не конструктор сеток. Гостя, которого нет в ростере, добавляют по имени прямо на чек-ине — в клубный список он не попадает.

Навигация: **Fencers | Tournaments | History | Stats** (иконка Trophy между людьми и историей). Список — `/tournaments`, карточка — `/tournaments/:id`.

### День события

1. **Список.** Незавершённые сверху. **New tournament** создаёт заготовку `setup`. Удаление только пока событие не `live`.
2. **Имя.** Обязательно; пустое поле подставляет дату. Лимиты времени и уколов — ползунки **этого** турнира, не клубные настройки устройства.
3. **Чек-ин.** Два способа: галочки по активному ростеру и **Add guest** (имя обязательно, клуб необязателен). Минимум двое, чтобы идти дальше. Плей-офф доступен только при ровно 2 / 4 / 8 / 16 / 32 отмеченных. У каждого участника хранится клуб: у своих — название клуба-организатора, у гостя — то, что ввели, или пусто. По ходу события клуб не показывается; после Finish — на вкладке Table.
4. **Формат.** Пять пресетов (ниже). Для круговой, групп и швейцарки нужна схема баллов — без выбора Start не открывается.
5. **Draw**, затем **Start event.** После Start состав, формат и схема заперты; назад к чек-ину нельзя. Царь горы жеребьёвки слотов не делает: сразу Start.
6. **Проведение.** Табы Queue / Table / Bouts (названия зависят от формата). Старт слота ведёт на табло. **Finish event** можно нажать в любой момент: места по уже сыгранному.
7. **Done.** Только таблица и список боёв; править счёт из Bouts всё ещё можно. На Table у имени — клуб участника, если он был задан.

### Пять форматов

| Экран | Когда | Что видит судья |
|---|---|---|
| Round robin | все со всеми | очередь пар, круговая таблица (баллы, +/- уколы) |
| Playoff | степень двойки ≤ 32 | сетка снизу вверх, финал внизу, бронза при `n≥4` |
| Groups + playoff | круговые блоки, потом та же сетка | таблица на группу + очередь плей-офф; выход с ничьей — **Choose** на строке |
| Swiss | туры по результатам | блоки туров; таблица как круговая; нечётный состав — зачёт без строки боя |
| King of the hill | очередь выходов, без сетки | список оставшихся выходов; на табло живые селекты |

Схема баллов, где нужна: `0 / 0.5 / 1`, `0 / 0 / 1`, `0 / 1 / 3` (поражение / ничья / победа).

**Группы.** Число групп 2 / 4 / 8 и сколько выходят из группы: произведение должно быть степенью двойки. Неровные размеры групп нормальны. Слоты плей-офф тусклые, пока выходы не назначены (включая ручной Choose при ничьей на срезе).

**Швейцарка.** Число туров считает само: `max(1, ⌈log₂ n⌉)`, в UI не правится. Следующий тур появляется, когда текущий весь сыгран.

**Царь горы.** Лимит выходов по умолчанию 3 (ползунок 1–10 до Start). Претендент тратит выход, сидящий царь — нет. Человек с нулём выходов всё ещё в списке как напоминание, но в красный пикер на табло не попадает. Ничья на табло = царь остаётся. Finish — когда вечер кончился.

### Табло

Слот сетки: `/?t=<tournamentId>&b=<boutId>`. Подставляются бойцы слота и лимиты турнира. Полоска с названием события и возвратом на карточку.

Царь горы: `/?t=<tournamentId>` без `b`. Селекты живые. После первого сохранённого боя синий по умолчанию — сидящий царь, красный — претендент из тех, у кого выходы ещё есть. Reset после Save ставит нового царя на синего и чистит претендента. Выбор можно сменить.

**Save** пишет турнирный бой, не клубный. Нет сети — ошибка на экране, слот (или селекты) остаются открытыми: турнирного outbox нет.

Ничья: круговая / группы / швейцарка — Save как ничья. Плей-офф — Save нельзя (как клубный бой с ничьей в правилах окончания, плюс попап). Царь горы — победа царя.

### Правка счёта

Из вкладки Bouts, не с табло и не из клубной истории. Меняются только уколы; пара остаётся. Статус победа/поражение/ничья пересчитывается из счёта. Плей-офф в ничью оверрайдом тоже нельзя. Уже сохранённые следующие бои сами не стираются; незаполненные слоты (плей-офф, будущие туры швейцарки) перепахиваются.

### Чего нет в v1

Несколько дорожек, пережеребьёвка после Start, победа без боя, снятие человека с сетки, очередь офлайн-сохранений, публичная сетка для зрителей.

## Технически

Источник правды для события, состава и протоколов — Supabase. Идущий счёт и таймер в сеть не ходят. Клиент — anon key, RLS `is_club_member(club_id)`.

### Модель

Схема: `supabase/migrations/20260913180000_tournaments.sql`, `supabase/migrations/20260915153000_tournament_guest_checkin.sql` и зеркало в `supabase/final_schema.sql`. Типы: `src/types/tournament.ts`, `src/types/database.ts`.

```text
tournaments
  id, club_id → clubs
  name                    -- trim, не пусто
  status                  -- setup | live | done
  format                  -- round_robin | playoff | groups_playoff | swiss | king_of_hill | null
  points_scheme           -- half | binary | football | null
  time_limit_sec          -- 60…300
  points_limit            -- 5…20
  group_count, advancers_per_group
  swiss_rounds
  koth_exit_limit         -- default 3, ≥ 1
  created_at, updated_at, live_at, finished_at

tournament_participants
  pk (tournament_id, fencer_id)   -- у гостя fencer_id не ссылается на fencers
  club_id                         -- клуб-организатор, для RLS
  name                            -- снимок на чек-ине
  club_name                       -- подпись в итогах; у ростера clubs.name, у гостя необязательно
  is_guest
  group_no                        -- для групп+плей-офф

tournament_bouts
  stage                   -- rr | group | swiss | playoff | koth
  group_no, round_code, sort_order
  blue/red_fencer_id, blue/red_placeholder
  winner_next_id, loser_next_id
  blue/red_name, score, result   -- result: win | lose | draw, text+check как matches
  time_limit_sec, points_limit, remaining_sec
  started_at, finished_at
  koth_king_id            -- только stage=koth; без FK на fencers (гость тоже может быть царём)
```

RLS на всех трёх таблицах: SELECT / INSERT / UPDATE / DELETE при `is_club_member(club_id)`. Участник из ростера должен быть `fencers` этого клуба; гость — `is_guest` и uuid, которого нет в `fencers`. Бойцы слота — участники этого турнира.

Турнирные бои **никогда** не пишутся в `matches`. Агрегаты `/history` и `/stats` читают только `matches`.

### Статусы и запись

```text
setup  -- имя, чек-ин, формат, (жеребьёвка)
  Start event → live  (live_at; состав/формат/схема дальше read-only)
live
  Finish event → done  (finished_at; можно и без полного графа)
done
  оверрайд счёта ещё разрешён
```

Удаление турнира — каскад участников и боёв; только из `setup`.

**Save слота** (круговая, группы, швейцарка, плей-офф): UPDATE существующего `tournament_bouts` — `finished_at`, счёт, снимок имён, `*_result` из счёта, лимиты боя. Не INSERT в `matches`.

**Save царя горы:** INSERT нового ряда `stage=koth`. Царь: победитель прошлого koth-боя этого турнира, если он снова на табло; иначе синий. В ряд кладётся `koth_king_id`.

Нет сети → ошибка, без `localStorage`-очереди. Клубный outbox `matches` к турниру не относится.

Оверрайд: тот же UPDATE счёта/результата. Дальше формат-специфичный пересчёт (места; placeholder плей-офф; швейцарка с `rebuildUnplayed`). Сыгранные следующие бои не удаляем.

### Форматы в коде

Чистые функции в `src/lib/tournament/*`, не в JSX. Запись в сеть — `src/lib/tournaments.ts` и `src/lib/tournamentBouts.ts`. Хуки: `useTournaments` (список), `useTournament` (карточка). Страницы: `Tournaments.tsx`, `Tournament.tsx`. Табло: `Index.tsx` + `TournamentScoreboardBar`. Навигация: `ClubNav`.

| Формат | Draw | Live |
|---|---|---|
| `round_robin` | полный граф, `sort_order` с отдыхом (`roundRobin.ts`, `restOrder.ts`) | Queue плоский; Table из `standings.ts` |
| `playoff` | дерево + бронза, `winner_next_id` / `loser_next_id` (`playoff.ts`); поздние слоты без id | Queue/Table — блоки раундов; Save наполняет следующий слот |
| `groups_playoff` | пары в группах + дерево с placeholder `g{n}p{k}` (`groups.ts`) | placeholder резолвятся при Start и когда группа закрыта; Choose пишет выбранный id в слот |
| `swiss` | только тур 1 (`swiss.ts`) | следующий тур, когда все `finished_at` текущего; bye — баллы победы по схеме, 0 уколов, без ряда боя |
| `king_of_hill` | боёв нет (`kingOfHill.ts`: выходы, серии, титулы) | очередь = remaining exits; табло без `b` |

**Швейцарка, sync.** `syncSwiss(id)` на live Save **не** дропает несыгранные туры — иначе каждый синг пересобирает тур 2. Пересборка несыгранного — только оверрайд: `syncSwiss(id, { rebuildUnplayed: true })`. Признак «нужен следующий тур» — `swissNeedsNextRound`.

**Плей-офф.** Критерий отдыха не применяется. Draw и оверрайд с равным счётом запрещены.

**Царь горы.** Лимит выходов не энфорсится на Save: это очередь и фильтр красного пикера, не замок. После Save клиент ставит победителя на синего.

### Зависимости окружения

Турниры есть только в клубном аккаунте (ключи Supabase + вход). Без ключей и в Quick bout иконка Tournament в `ClubNav` всё равно видна на табло, но страницы показывают ту же заглушку, что ростер. Гость с логина до клубных маршрутов не допускается.

Env те же: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`.
